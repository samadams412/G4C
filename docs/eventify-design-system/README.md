# Eventify design system

Eventify is an event discovery and ticketing platform. This system replaces the current ad hoc rainbow of unrelated colors (orange logo, pink headline accent, purple buttons, teal/orange/purple card borders) with one derived, systematic palette — built with Google's Material Design 3 (M3) color algorithm from a single seed color — plus a type, spacing, and radius scale to match.

## Content fundamentals

**Seed color.** `#B2501B`, a burnt-terracotta orange. It was chosen to keep continuity with Eventify's existing orange wordmark while running it through M3's HCT (Hue, Chroma, Tone) algorithm to generate a disciplined, harmonious role-based palette instead of hand-picked, unrelated accent colors. Every color token in this system — light and dark — is derived from that one seed, not chosen independently.

**Scheme variant.** M3's default "TonalSpot" scheme deliberately desaturates — reads as calm and enterprise, not energetic. This system uses M3's **Vibrant** scheme variant instead: same seed, same role system, substantially higher chroma throughout (`primary` is a real burnt orange, not a muted brown). Better fit for a ticketing/events product that wants to feel alive.

**Personality.** Warm, editorial, tactile — closer to a concert poster or a local food-festival flyer than a corporate SaaS dashboard. This is the deliberate alternative to the generic "rounded card, soft shadow, purple-to-blue gradient" look most event platforms default to.

## Visual foundations

### Color

Tokens follow the M3 role system: `primary`/`secondary`/`tertiary` each have a base, an `on-` (foreground-on-fill) pair, and a `-container` (lower-emphasis surface) pair with its own `on-` pair. `surface-container-*` gives a 5-step elevation ramp used instead of drop shadows or colored borders for depth. Every token has both a `light` and `dark` value — dark mode is a first-class target, not an afterthought.

**Usage rules:**
- Primary actions (Register, Reserve tickets, Buy now) use `primary` fill with `on-primary` text. Only one `primary`-filled control per screen/section — competing primary buttons flatten the hierarchy.
- Category chips and tags use `secondary-container` fill with `on-secondary-container` text — never the raw `secondary` color, which is reserved for outlined buttons and links.
- Urgency/availability badges ("Selling fast," "3 left") use `tertiary-container` / `on-tertiary-container` — a distinct third hue so urgency never gets confused with a primary action or an error.
- Sold-out / destructive states (cancel a ticket) use `error` / `error-container` — never repurpose `tertiary` for this.
- Event cards sit on `surface-container`; a sticky order-summary panel or anything that should read as "above" the page sits on `surface-container-high`; modals and the selected ticket tier use `surface-container-highest`. This elevation ramp replaces today's colored card borders entirely — depth comes from tone, not hue.
- Default dividers and input borders use `outline`; decorative, low-emphasis dividers use `outline-variant`.
- Body copy on any surface uses `on-surface`; secondary/muted copy (event subtext, metadata) uses `on-surface-variant`.

### Typography

Two families, paired deliberately rather than defaulting to one grotesk for everything:

- **Display** (`Fraunces`): event titles, page headlines ("Upcoming events"). An editorial serif with real character — gives Eventify a poster/zine feel instead of a dashboard feel.
- **Sans** (`Public Sans`): everything else — body copy, labels, buttons, form fields, chips.

Type scale follows M3's five tiers (Display → Headline → Title → Body → Label), each with three sizes. Event titles on cards use `title-large`; the event detail page headline uses `headline-large` or `display-small`; category chip labels and button text use `label-large`.

### Spacing and shape

Spacing is an 8px-rooted scale (`space-4` through `space-48`) — pick the smallest token that gives a control room to breathe rather than eyeballing margins. Radius has four steps: `radius-sm` (8px) for buttons and text fields, `radius-md` (12px) for cards and dialogs, `radius-lg` (16px) for bottom sheets, `radius-full` for pills (filter chips, badges, avatars).

## Iconography

Material Symbols (outlined style) is the natural pairing with an M3-derived system and is free to use. Keep to one weight/style throughout — mixing outlined and filled icons undercuts the "deliberate system" the rubric is grading for.

## Accessibility

All `on-*` / surface pairs in this system were generated by M3's contrast-aware algorithm and meet WCAG AA text contrast (4.5:1 body, 3:1 large text) in both light and dark themes. Don't substitute a token's paired `on-*` color for another — the pairing is what guarantees the contrast.
